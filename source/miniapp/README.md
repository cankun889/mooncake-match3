## 中文

本目录是 TuyaOpen IDE 创建面板小程序时使用的脚手架模板，基于 **Ray.js** 框架（React 子集）。

### 目录结构

```
source/miniapp/               ← 项目根（project.tuya.json 所在层）
├── project.tuya.json         ← Tuya 平台元数据（appid、kit 版本、发版号）
├── package.json              ← 依赖：@ray-js/{ray,panel-sdk,cli,smart-ui}
├── tsconfig.json
├── ray.config.ts             ← 构建配置（webpack alias）
├── typings/                  ← Tuya Kit 类型定义（不要手动修改）
│   ├── tuya-miniapp__BaseKit/
│   ├── tuya-miniapp__DeviceKit/
│   ├── tuya-miniapp__MediaKit/
│   └── ...（共 10 个 Kit）
└── src/
    ├── app.tsx               ← App 启动（SdmProvider + 预览 shim 安装）
    ├── app.config.ts         ← 全局窗口配置 + 页面注册列表
    ├── app.less              ← 全局主题 token（--app-B1/B2/T1/T2/T3/M4）
    ├── ty-shim.ts            ← IDE 本地预览模拟层（生产包不含此逻辑）
    ├── routes.config.ts      ← 路由表（与 app.config.ts 的 pages 对应）
    ├── global.config.ts      ← 全局窗口常量
    ├── config/
    │   └── dpCodes.ts        ← DP code 常量（IDE 同步时自动覆盖）
    ├── devices/
    │   ├── schema.ts         ← DP 定义（IDE 自动生成，禁止手改）
    │   └── index.ts          ← SmartDeviceModel + dpKit 实例
    ├── pages/
    │   └── home/
    │       ├── index.tsx
    │       ├── index.config.ts
    │       ├── index.module.less
    │       └── components/   ← 页面级子组件
    └── utils/
        └── ota.ts            ← OTA 升级工具
```

### 核心概念

#### DP 读写

**禁止用 `useState` 管理 DP 值**，必须走 `@ray-js/panel-sdk` 提供的 hook：

```tsx
import { useProps, publishDpOutTime } from '@ray-js/panel-sdk';

// 读 DP（响应式，设备推送时自动刷新）
const isOn = useProps(p => p.switch as boolean);

// 写 DP（自带 Loading + 超时 10s + 失败 Toast）
publishDpOutTime('switch', true);
```

对于 `raw` / JSON 类型的复杂 DP，使用 `useStructuredProps` + `useStructuredActions`，并在 `protocols/index.ts` 注册 Transformer。

#### 主题颜色

颜色通过 `src/app.less` 的 `:root {}` 统一定义，深色模式用 `:root[theme='dark'] {}`。
`.module.less` 里始终用 `var(--app-X, fallback)` 引用，不要硬编码颜色。

| 变量 | 用途 |
|------|------|
| `--app-B1` | 卡片背景 |
| `--app-B2` | 页面背景 |
| `--app-T1` | 主文字 |
| `--app-T2` | 次文字 |
| `--app-T3` | 辅助文字 |
| `--app-M4` | 品牌强调色 |

#### 样式规范

- 每个组件/页面必须有独立的 `.module.less`，通过 `import styles from './index.module.less'` 使用
- 禁止全局 class，禁止内联 `style={{}}`

### 开发流程

```bash
# 安装依赖（首次或更新 package.json 后）
npm install

# 本地预览（IDE 内嵌浏览器 或 http://localhost:8080）
npm run dev        # 或 ray start --target web

# 构建生产包
npm run build      # 或 ray build --target tuya
```

### 新增页面

1. 新建 `src/pages/<name>/index.tsx`（以及 `index.config.ts`、`index.module.less`）
2. 在 `src/app.config.ts` 的 `pages` 数组加入 `'pages/<name>/index'`
3. 在 `src/routes.config.ts` 补充对应路由

未在 `app.config.ts` 登记的页面无法路由，会静默失败。

### 新增 Kit 类型定义

当你需要使用 typings 里尚未包含的 Kit（如 MapKit 已内置，AIKit 已内置），或需要更新版本：

```bash
# 1. 查询可用版本（registry 无需登录）
npm info @tuya-miniapp/SomeKit --registry https://registry-npm.tuya-inc.top

# 2. 下载并提取类型文件
cd /tmp
npm pack @tuya-miniapp/SomeKit@x.y.z --registry https://registry-npm.tuya-inc.top
mkdir -p <项目>/source/miniapp/typings/tuya-miniapp__SomeKit
tar -xzOf tuya-miniapp-somekit-*.tgz package/@types/index.d.ts \
  > <项目>/source/miniapp/typings/tuya-miniapp__SomeKit/index.d.ts
rm -rf package tuya-miniapp-somekit-*.tgz

# 3. 声明运行时版本（手机端 App 按此加载 Kit）
# 编辑 project.tuya.json 的 dependencies：
# "SomeKit": "x.y.z"
```

`tsconfig.json` 已配置 `typeRoots: ["./typings", ...]`，新目录无需额外配置即可生效。

This directory is the scaffold template used by TuyaOpen IDE when creating a panel mini-app, built on the **Ray.js** framework (a React subset).

### Directory Structure

```

├── project.tuya.json         ← Tuya platform metadata (appid, kit versions, release version)

├── tsconfig.json
├── ray.config.ts             ← build config (webpack aliases)
├── typings/                  ← Tuya Kit type definitions (do not edit manually)
│   ├── tuya-miniapp__BaseKit/
│   ├── tuya-miniapp__DeviceKit/
│   ├── tuya-miniapp__MediaKit/
│   └── ... (10 kits total)
└── src/
    ├── app.tsx               ← App entry (SdmProvider + preview shim install)
    ├── app.config.ts         ← Global window config + page registration
    ├── app.less              ← Global theme tokens (--app-B1/B2/T1/T2/T3/M4)
    ├── ty-shim.ts            ← IDE local preview shim (stripped from production)
    ├── routes.config.ts      ← Route table (must match app.config.ts pages)
    ├── global.config.ts      ← Global window constants
    ├── config/
    │   └── dpCodes.ts        ← DP code constants (auto-overwritten by IDE sync)
    ├── devices/
    │   ├── schema.ts         ← DP schema (auto-generated by IDE, do not edit)
    │   └── index.ts          ← SmartDeviceModel + dpKit instance
    ├── pages/
    │   └── home/
    │       ├── index.tsx
    │       ├── index.config.ts
    │       ├── index.module.less
    │       └── components/   ← page-scoped sub-components
    └── utils/
        └── ota.ts            ← OTA upgrade helper
```

### Core Concepts

#### Reading and Writing DPs

**Never use `useState` to manage DP values.** Always use hooks from `@ray-js/panel-sdk`:

```tsx
import { useProps, publishDpOutTime } from '@ray-js/panel-sdk';

// Read DP (reactive — auto-refreshes on device push)
const isOn = useProps(p => p.switch as boolean);

// Write DP (includes built-in loading, 10s timeout, and failure toast)
publishDpOutTime('switch', true);
```

For `raw` / JSON-encoded complex DPs, use `useStructuredProps` + `useStructuredActions` and register a Transformer in `protocols/index.ts`.

#### Theme Colors

Colors are defined once in `src/app.less` under `:root {}`. Dark mode overrides go in `:root[theme='dark'] {}`. Always reference them with `var(--app-X, fallback)` in `.module.less` — never hardcode color values.

| Variable | Role |
|----------|------|
| `--app-B1` | Card / surface background |
| `--app-B2` | Page background |
| `--app-T1` | Primary text |
| `--app-T2` | Secondary text |
| `--app-T3` | Hint / caption text |
| `--app-M4` | Brand accent color |

#### Styling Rules

- Every component/page must have its own `.module.less`, imported as `import styles from './index.module.less'`
- No global class names; no inline `style={{}}`

### Development

```bash
# Install dependencies (once, or after package.json changes)
npm install

# Local preview (IDE embedded browser or http://localhost:8080)
npm run dev        # or: ray start --target web

# Production build
npm run build      # or: ray build --target tuya
```

### Adding a New Page

1. Create `src/pages/<name>/index.tsx` (plus `index.config.ts` and `index.module.less`)
2. Add `'pages/<name>/index'` to the `pages` array in `src/app.config.ts`
3. Add the matching route to `src/routes.config.ts`

Pages not registered in `app.config.ts` are silently unreachable.

### Adding a Kit Type Definition

When you need a Kit not yet in `typings/` (MediaKit, MapKit, P2PKit are already bundled), or need to update a version:

```bash
# 1. Query available versions (registry requires no login)
npm info @tuya-miniapp/SomeKit --registry https://registry-npm.tuya-inc.top

# 2. Download and extract the type file
cd /tmp
npm pack @tuya-miniapp/SomeKit@x.y.z --registry https://registry-npm.tuya-inc.top
mkdir -p <project>/source/miniapp/typings/tuya-miniapp__SomeKit
tar -xzOf tuya-miniapp-somekit-*.tgz package/@types/index.d.ts \
  > <project>/source/miniapp/typings/tuya-miniapp__SomeKit/index.d.ts
rm -rf package tuya-miniapp-somekit-*.tgz

# 3. Declare the runtime version (phone App loads the Kit based on this)
# Edit project.tuya.json → dependencies:
# "SomeKit": "x.y.z"
```

`tsconfig.json` already has `typeRoots: ["./typings", ...]` — new directories are picked up automatically.
